## Goal

A command-line runner, `ds4macos run`, that owns or shares the controller according to the
profile's mode, turns its input into keyboard and mouse events through a mapping engine with proper
analogue handling, drives the lightbar, triggers and rumble from the same engine, survives
unplugging and reconnecting, and lets the owner play Fallout 4 on built-in profiles in two modes:
`keyboardMouse` (full remap) and `augment` (the game keeps the real pad, the app adds feedback).
The menu bar app (M4) wraps this runner; profile files (M3) feed it; the XInput proxy (M3b) plugs
into the same engine as a third mode.

## Tasks

### M2-T1: Profile model and mapping engine

- Agent: coder
- Owns: `Sources/DualSenseCore/Profile/`, `Sources/DualSenseCore/Mapping/`, tests
- Do:
  1. `Profile` (Codable, `formatVersion: Int = 1`): `name`, `mode: ProfileMode` (`.augment`,
     `.keyboardMouse`, `.proxy`), `appBundleIDs: [String]` (M3 uses it), `buttons: [ButtonID:
     Binding]` where `ButtonID` is a Codable enum over the DualSense buttons plus the four dpad
     directions, `leftStick`/`rightStick: StickBinding`, `l2`/`r2: TriggerBinding`, `touchpad:
     TouchpadBinding`, `lightbar: RGB?`, `leftTriggerEffect`/`rightTriggerEffect: TriggerEffect?`,
     `rumbleOnTrigger: RumblePulse?` (strong, weak, durationMs, which trigger), `playerLEDs: UInt8?`.
     `Binding`: `.key(code: UInt16)`, `.mouseButton(MouseButton)`, `.scroll(dy: Int)`, `.none`.
     `StickBinding`: `.wasd(threshold: Float = 0.5, hysteresis: Float = 0.1)`, `.mouse(sensitivity:
     Double, curve: Double, deadZone: Float)`, `.none`. `TriggerBinding`: `.button(Binding, threshold:
     Float)`, `.none`. `TouchpadBinding`: `layout: TouchZoneLayout` plus `[ZoneIndex: [GestureKind:
     Binding]]`, where `GestureKind` covers tap, twoFingerTap, hold, swipeUp/Down/Left/Right, click.
     Make `TriggerEffect`, `TouchZoneLayout`, `TouchRect` and `RGB` Codable if they are not yet.
  2. `MappingEngine`: `init(profile:)`, `update(state: ControllerState, gestures: [GestureEvent],
     at: TimeInterval) -> MappingOutput` with `actions: [OutputAction]` and `feedback:
     [FeedbackAction]`. `OutputAction`: `.keyDown(code)`, `.keyUp(code)`, `.mouseMove(dx: Double,
     dy: Double)`, `.mouseDown(MouseButton)`, `.mouseUp(MouseButton)`, `.scroll(dy)`.
     `FeedbackAction`: `.rumble(strong:weak:durationMs:)`, `.lightbar(RGB)`, `.trigger(TriggerSide,
     TriggerEffect)`, `.playerLEDs(UInt8)`. The engine tracks what is held so it emits transitions
     only; `releaseAll() -> [OutputAction]`; `initialFeedback() -> [FeedbackAction]` for the
     profile's static outputs. In `augment` mode, bindings with `.none` emit nothing (the game has the
     pad); in `keyboardMouse` mode everything unbound is simply unbound. `proxy` mode is accepted by
     the model but the engine treats it as `augment` for now (M3b replaces this).
     Mouse movement from a stick integrates velocity over elapsed time (so 250 Hz and 65 Hz feel
     the same) and carries the fractional remainder. Gesture bindings fire as a 40 ms key tap
     (down, then up on a later update) so games register them.
  3. Built-ins (`Profile.builtIns: [Profile]`):
     - `fallout4KeyboardMouse`: left stick WASD, right stick mouse (900 px/s, curve 1.6, dead zone
       0.12), R2 left mouse, L2 right mouse, Cross E (14), Circle Ctrl (59), Square R (15), Triangle
       Space (49), L1 Shift (56), R1 V (9), L3 Shift, R3 Q (12), Options Esc (53), Create Tab (48),
       dpad up/down/left/right 1/2/3/4 (18/19/20/21), touchpad left-half tap Tab, right-half tap M
       (46), swipe up/down scroll. Lightbar blue. R2 weapon effect, L2 light feedback, rumble pulse
       120 ms on R2.
     - `fallout4Augment`: mode `augment`, no key bindings at all (Fallout 4 ignores the keyboard in
       controller mode), same feedback as above.
     - `genericAugment`: mode `augment`, touchpad left-half tap Tab, right-half tap M, swipe up/down
       scroll, two-finger tap Esc, everything else `.none`, same feedback.
     - `passThrough`: mode `augment`, nothing bound, no feedback.
  4. Tests: transitions only (a held button emits one keyDown); WASD hysteresis; mouse velocity
     integration at 250 Hz and 65 Hz gives the same distance for the same deflection over one
     second; radial dead zone; gesture tap down/up timing; `releaseAll` after a mix of held inputs;
     every built-in profile round-trips through JSON; augment mode emits no actions for unbound
     buttons.
- Accept when: `scripts/swift test` passes with at least 25 new tests.

### M2-T2: DeviceManager

- Agent: coder
- Owns: `Sources/DS4Mac/DeviceManager.swift`, `Sources/DS4Mac/OutputScheduler.swift`, and the M0
  `HIDDevice.swift` (refactor allowed)
- Do:
  1. IOHIDManager matching for both product IDs; device-matched and device-removed callbacks; a
     closure API: `onState(ControllerState)`, `onConnect(ConnectionInfo)` (transport, firmware
     update version, vibration mode), `onDisconnect`.
  2. `open(seize: Bool)`: `augment` opens without seize, the other modes with it. `reopen(seize:)`
     closes and reopens so a profile change at runtime switches modes without restarting.
  3. On connect: read feature `0x20` (64 bytes) and derive `VibrationMode.forUpdateVersion`; on
     Bluetooth also read feature `0x05` (41 bytes) so full reports start; then start the input
     callback. Decode with `InputDecoder`; count undecodable reports; expose `droppedReports`.
  4. If both a USB and a Bluetooth device are present for the same pad, open both the same way,
     use USB for input and output, and log it.
  5. `OutputScheduler`: holds the desired output state (lightbar, triggers, player LEDs, rumble with
     expiry); sends a report when something changed, when a rumble expired, and, in `augment` mode,
     every 2 s regardless (CrossOver's driver overwrites outputs); never more often than every 10 ms;
     framed for the transport (USB `0x02`; Bluetooth `0x31` with the running sequence counter, after
     one `OutputReport.lightbarSetup()` on connect).
  6. On disconnect: notify so held keys get released; on reconnect: reapply the desired output state.
- Accept when: macOS CI builds it with no warnings; the reviewer checks every IOKit call signature
  against Apple's documentation via WebFetch; the Bluetooth output path uses M1's framing.
