## Goal

A command-line runner, `ds4macos run`, that owns the controller from the moment it connects (USB or
Bluetooth, seized), turns its input into keyboard and mouse events through a mapping engine with
proper analogue handling, drives the lightbar, triggers and rumble from the same engine, survives
unplugging and reconnecting, and lets the owner play Fallout 4 for ten minutes on a built-in profile
without touching the keyboard. The menu bar app (M4) wraps this runner; the profile files (M3) feed it.

## Tasks

### M2-T1: Profile model and mapping engine

- Agent: coder
- Owns: `Sources/DualSenseCore/Profile/`, `Sources/DualSenseCore/Mapping/`, tests
- Do:
  1. `Profile` (Codable, versioned with a `formatVersion` field): name, `appBundleIDs: [String]`
     (for M3's auto-switch; unused now), `buttons: [DualSenseButton: Binding]`,
     `leftStick`/`rightStick: StickBinding`, `l2`/`r2: TriggerBinding`, `touchpad: TouchpadBinding`,
     `lightbar: RGB?`, `leftTriggerEffect`/`rightTriggerEffect: TriggerEffect?`,
     `rumbleOnTrigger: Bool`. `Binding` is an enum: `.key(code)`, `.mouseButton(.left/.right/.middle)`,
     `.scroll(dy)`, `.none`. `StickBinding`: `.wasd(threshold: 0.5, hysteresis: 0.1)`,
     `.mouse(sensitivity: pxPerSecondAtFullDeflection, curve: exponent, deadZone: radial 0.12)`,
     `.none`. `TriggerBinding`: `.button(Binding, threshold: 0.5)`. `TouchpadBinding`: zone grid
     plus `[GestureKind: Binding]` per zone, swipe directions included.
  2. `MappingEngine`: `update(state: ControllerState, gestures: [GestureEvent], at: TimeInterval)
     -> (actions: [OutputAction], feedback: [FeedbackAction])`. `OutputAction`: `.keyDown(code)`,
     `.keyUp(code)`, `.mouseMove(dx: Double, dy: Double)`, `.mouseDown(button)`, `.mouseUp(button)`,
     `.scroll(dy)`. `FeedbackAction`: `.rumble(strong:weak:durationMs:)`, `.lightbar(RGB)`,
     `.trigger(side, TriggerEffect)`. The engine tracks what is held so it emits transitions only,
     and `releaseAll()` returns the up-actions for everything held. Mouse movement from a stick
     integrates velocity over the time since the last update (so 250 Hz and 65 Hz feel the same)
     and carries the fractional remainder.
  3. `Profile.fallout4Default`: left stick WASD, right stick mouse (sensitivity 900 px/s, curve 1.6),
     R2 left mouse button, L2 right mouse button, Cross E, Circle Ctrl (crouch, keycode 59), Square R,
     Triangle Space, L1 Shift (sprint), R1 V (VATS), L3 Shift, R3 Q (favourites), Options Esc,
     Create Tab (Pip-Boy), dpad up/down/left/right to 1/2/3/4, touchpad left-half tap Tab, right-half
     tap M, swipe up/down scroll, PS button `.none`. Lightbar blue. R2 trigger effect: weapon-style
     resistance; L2 light resistance; rumble a 120 ms pulse on R2 past threshold.
     `Profile.passThrough`: everything `.none`, no feedback.
  4. Tests: transitions only (a held button emits one keyDown); WASD hysteresis; mouse velocity
     integration at both report rates gives the same distance for the same deflection over one
     second; radial dead zone; `releaseAll` after a mix of held inputs; profile round-trips through
     JSON.
- Accept when: `scripts/swift test` passes with at least 25 new tests.

### M2-T2: DeviceManager

- Agent: coder
- Owns: `Sources/DS4Mac/DeviceManager.swift`, `Sources/DS4Mac/OutputScheduler.swift`, and the M0
  `HIDDevice.swift` (refactor allowed)
- Do:
  1. IOHIDManager matching for both product IDs; device-matched and device-removed callbacks; a
     `delegate`/closure API: `onStateChange(ControllerState)`, `onConnect(transport)`, `onDisconnect`.
  2. On connect: open with seize (configurable, default on); on Bluetooth, read feature report
     `0x05` with a 41-byte buffer to enable full reports, then start the input callback; on USB, start
     the callback directly. Decode each buffer with `InputDecoder`; drop and count undecodable ones.
  3. If both a USB and a Bluetooth device are present for the same pad, seize both, use USB for input
     and output, and log it.
  4. `OutputScheduler`: holds the desired output state (lightbar, triggers, rumble with expiry), sends a
     report only when something changed or a rumble expired, at most every 10 ms, framed for the
     device's transport (USB `0x02`, Bluetooth `0x31` with the running sequence counter and CRC).
  5. On disconnect: tell the delegate so held keys get released; on reconnect: reapply the desired
     output state.
- Accept when: the macOS CI job builds it with no warnings; the reviewer checks every IOKit call
  signature against Apple's documentation via WebFetch; the Bluetooth output path uses M1's framing.

### M2-T4: `ds4macos` runner

- Accept when: builds on macOS CI with no warnings; `swift run ds4macos permissions` logic is
  reviewed; the reviewer checks that every exit path calls `releaseAll`.

- Agent: lead

  6. Pass-through toggle: press `p`, confirm the game now sees the controller (after a game restart);
     press `p` again.
  7. Hot-plug: unplug the cable mid-game (pad may fall to Bluetooth), replug; the runner must keep
     working without a restart, and nothing stays held.
  8. Report rates and decode error counts from the status line, both transports.
