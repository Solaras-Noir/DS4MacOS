# M2 Mac test protocol

Run by the owner with a local Claude Code session (Sonnet), DualSense in hand, Fallout 4 in a
CrossOver bottle. Work on branch `m2/mac`, created from `main` after the M2 cloud PR is merged.
Go one step at a time. Record every result in `docs/mac-tests/M2-results.md` (copy the results table at
the bottom, then fill it in). Run every command from **Terminal.app** in the repo root: macOS grants
Accessibility and Input Monitoring to the terminal app, not to the binary.

Stop and write the question under "Questions" in the results file if a step needs `sudo`, an
entitlement, or the process to be the foreground app (these are "ask the architect" items).

Binaries after `scripts/swift build`: `.build/debug/ds4macos` and `.build/debug/ds4probe`. The
commands below use `scripts/swift run`, which works the same way.

## 1. Build and tests

```
git checkout main && git pull && git checkout -b m2/mac
scripts/swift build
scripts/swift test
```

Expected: builds with no warnings in `DS4Mac` or `ds4macos`; all tests pass. Record the test count.

## 2. M1 hardware checks (USB and Bluetooth)

```
scripts/swift run ds4probe list
scripts/swift run ds4probe firmware
scripts/swift run ds4probe read
```

Expected over USB: one device, firmware update version 0x0633 (or what M1 recorded), `read` prints
decoded state. Unplug the cable, pair over Bluetooth (hold PS + Create), then:

```
scripts/swift run ds4probe read
scripts/swift run ds4probe rumble 200 0 --ms 500
```

Expected: `read` decodes `0x31` reports (sticks, buttons, touchpad move the values); the rumble is felt
for about half a second (default vibration variant v2).

## 3. XInput stub load test (decides M3b)

Follow `probes/xinput-stub/README.md` ("Install for Fallout 4 under CrossOver"). Unplug and unpair the
controller first so the game sees only the synthetic pad. Two launches:

1. A clean `Fallout4.exe` launch from the bottle (no F4SE), through to the main menu.
2. The same with F4SE.

After each, read `<bottle>/drive_c/users/crossover/Temp/xinput-stub.log`. Record in the table:
reaches main menu (yes/no), log shows polling lines (yes/no), the synthetic A press is seen in the
menu (yes/no), any `XInputSetState` lines. Remove the DLLs and the overrides afterwards.
If it fails, paste the Wine console output for the failed load into the results file.

## 4. `keyboardMouse` play test (Fallout 4)

```
scripts/swift run ds4macos permissions
```

Expected: reports Accessibility granted (grant it for Terminal in System Settings if not, then
restart Terminal). Reconnect the controller by USB, then start the runner **before** launching the game:

```
scripts/swift run ds4macos run --profile fallout4KeyboardMouse
```

Expected: a status line every 5 s with mode `keyboardMouse`, transport, firmware, report rate and
dropped reports. Launch Fallout 4 and play for ten minutes. One results row per action
(PASS / FAIL / PARTIAL, plus feel notes on sensitivity and dead zone):

walk (left stick), sprint (L1 or L3, Shift), look (right stick), aim (L2, right mouse), fire (R2, left
mouse), reload (Square, R), crouch (Circle, Ctrl), jump (Triangle, Space), interact (Cross, E), Pip-Boy
(Create, Tab), favourites (dpad, keys 1-4), VATS (R1, V), map (touchpad right-half tap, M), dpad hotkeys 1 to 4, touchpad left tap and swipes up/down (scroll).
Also note: R2 resistance and the 120 ms rumble pulse on fire, the lightbar colour (blue).
Quit with Ctrl-C and confirm nothing stays held (no stuck W or mouse button).

## 5. `augment` play test (Fallout 4)

Quit the game completely, then:

```
scripts/swift run ds4macos run --profile fallout4Augment
```

Launch Fallout 4 afterwards. Expected: the game sees the real pad and plays normally with analogue
sticks; R2 shows weapon resistance; a rumble pulse on fire; the lightbar stays blue while the game has
focus (the 2 s re-assert). Mod hotkeys, either way:

- bind one MCM hotkey to F6 or F7 and tap the touchpad left or right half; or
- `scripts/swift run ds4macos export-profile fallout4Augment ~/f4.json`, edit the touchpad keys to
  hotkeys your mods already use, then `scripts/swift run ds4macos run --profile ~/f4.json`.

Expected: a touchpad tap triggers the mod action while the sticks keep working. Record whether the
input callback stays alive while CrossOver also has the pad (it must not starve).

## 6. `genericAugment` in a mixed-input game

```
scripts/swift run ds4macos run --profile genericAugment
```

Use a game that accepts keyboard alongside a controller (Baldur's Gate 3 or an indie from the bottle).
Expected: sticks work natively, touchpad left tap fires Tab, right tap M, two-finger tap Esc, swipes scroll.

## 7. Pass-through toggle

With a runner active, press `p` in the Terminal. Expected: all keys released, nothing injected, the
status line says pass-through; confirm the game sees the pad (restart the game if it needs to). Press
`p` again: the runner reopens in the profile's mode and injection resumes.

## 8. Hot-plug

With a runner active in game, unplug the cable (the pad may fall to Bluetooth), then replug. Expected:
the runner keeps working without a restart, outputs (lightbar, triggers) are reapplied, nothing stays
held. Repeat once with the Bluetooth link only (turn the pad off and on). If the connect/disconnect
callbacks do not fire, record it: DeviceManager does not call `IOHIDManagerOpen`, and the fix is to open the
manager (see the M2 review notes in the session report).

## 9. Rates

From the status line, record the report rate and dropped-report count for each transport (USB, then
Bluetooth) after a minute of play.
