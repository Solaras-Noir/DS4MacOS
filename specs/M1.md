## Goal

`DualSenseCore` understands everything the controller sends over USB and Bluetooth, can build every
output the app will ever need (lightbar, player LEDs, rumble that actually rumbles, named trigger
effects, mic LED) for both transports, and turns raw touchpad contacts into gestures. All of it tested
on Linux against the fixtures captured in M0. Plus two small fixes the M0 Mac tests asked for.

## Context the lead needs

- M0 is merged. Read `docs/mac-tests/M0-results.md` first: it has the measured facts (the IOKit
  callback buffer includes the report ID, USB 250 Hz, Bluetooth 65 Hz, feature report `0x05` is 41
  bytes, fixture value checks).
- `docs/protocol/dualsense-hid.md` is the architect's starting notes; T1 replaces it with a sourced
  version and T2 onward implement from that version, not from memory.
- Fixtures exist: 18 `usb-*.hex` and 2 `bt-*.hex` under `Tests/DualSenseCoreTests/Fixtures/`.
  Format: first column is the callback's report ID, then the buffer, which also starts with the ID.
- Two M0 bugs are fixed here. Rumble: the builder sets `valid_flag0 = 0x01`; the Linux driver sets
  `0x03` (haptics select plus compatible vibration) whenever it updates the motors, and sets
  `valid_flag2 |= 0x04` as well on firmware 0x0224 or newer. XInput stub: Fallout 4 resolves the
  functions by ordinal, and the stub's named exports have arbitrary ordinals.
- Work flow for this milestone (new): the coder commits its own task when its tests pass; the
  reviewer reviews that commit (`git show`); a failed review means a follow-up commit by the coder,
  never an amend. Independent tasks run as parallel subagents. The lead's job is to dispatch, read
  the reports, and keep the running session report current. It should not read source files itself
  unless a report is contradictory.
