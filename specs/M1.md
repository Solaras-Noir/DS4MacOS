## Goal

`DualSenseCore` understands everything the controller sends over USB and Bluetooth, can build every
output the app will ever need (lightbar, player LEDs, rumble, named trigger effects, mic LED) for both
transports, and turns raw touchpad contacts into gestures. All of it tested on Linux with no hardware.

## Context the lead needs

- `docs/protocol/dualsense-hid.md` is the architect's starting notes; T1 replaces it with a sourced
  version and T2 onward implement from that version, not from memory.
- Fixtures from the M0 Mac session may or may not have landed when this starts. Tasks that need
  them say so; the lead reorders around that.
- The gesture engine is the heart of the touchpad feature the owner cares about most. It must be
  deterministic and testable with synthetic sequences of `TouchPoint`s and timestamps.

## Deliverables

- [ ] `docs/protocol/dualsense-hid.md` rewritten with sources, every offset cited, no UNVERIFIED items
      left that the code depends on
- [ ] Bluetooth input parsing (`0x31` with CRC check, simple `0x01`) and the feature report request
      that enables full mode, as pure functions and byte builders in the core
- [ ] Bluetooth output report building with sequence tag and CRC32
- [ ] `TriggerEffect` with named cases (off, feedback, weapon, vibration, multiplePositionFeedback,
      slopeFeedback, multiplePositionVibration) encoding to the mode and parameter bytes
- [ ] `ControllerState`: a normalised, transport-independent snapshot (axes with dead zone applied by
      the caller, buttons, triggers, touches, battery, timestamp)
- [ ] `TouchGestureEngine`: zones, tap, two-finger tap, hold, swipe with direction, drag with delta
- [ ] CRC32 implementation with test vectors
- [ ] Fixture tests covering USB and Bluetooth captures when present

## Tasks

### M1-T1: Sourced protocol document

- Agent: researcher
- Owns: `docs/protocol/dualsense-hid.md`
- Do: rewrite the file from the Linux driver (`drivers/hid/hid-playstation.c`, fetch via

  TriggerEffectGenerator and flok/pydualsense. Keep the same section layout. Resolve every item the
  current file marks **verify**. Add a trigger effect table: mode byte, parameter layout, value ranges.
- Accept when: every offset and flag has a source; the reviewer spot-checks five offsets against the
  kernel struct.

### M1-T2: CRC32 and Bluetooth framing

- Agent: coder
- Depends on: T1
- Owns: `Sources/DualSenseCore/CRC32.swift`, `Sources/DualSenseCore/BluetoothFraming.swift`, tests
- Do: table-driven CRC-32 (reflected, `0xEDB88320`); `verify(inputReport:)` for 78-byte `0x31`
  reports using seed `0xA1`; `frame(outputCommon:sequence:)` producing the 78-byte `0x31` output
  with seed `0xA2`; `InputReport.init?(bluetoothReport:)` handling `0x31` (full) and `0x01` (simple:
  sticks and buttons only, flag the report as `simple`).
- Accept when: CRC test vectors pass (the standard `"123456789"` → `0xCBF43926`, plus one real
  captured Bluetooth report if fixtures exist); a `0x31` report with a flipped byte is rejected.

### M1-T3: Output reports complete

- Agent: coder
- Depends on: T1
- Owns: `Sources/DualSenseCore/OutputReport.swift`, `Sources/DualSenseCore/TriggerEffect.swift`, tests
- Do: named `TriggerEffect` cases with parameter validation (positions 0...9 or 0...8 as the
  reference says, forces 0...8), encoding per the protocol doc; `OutputReport.bluetoothBytes(sequence:)`;
  lightbar fade-out, mic LED modes, player LED patterns for players 1 to 4 and a raw mask; a
  `compatibleVibration2` switch that moves the rumble valid bit to flag2 for newer firmware.
- Accept when: each named effect has a test asserting its exact bytes against the reference
  encoding; USB and Bluetooth byte layouts agree on the common block.

### M1-T4: ControllerState and the input pipeline

- Agent: coder
- Depends on: T2
- Owns: `Sources/DualSenseCore/ControllerState.swift`, `Sources/DualSenseCore/InputDecoder.swift`, tests
- Do: `InputDecoder` that accepts any raw report (USB or Bluetooth, with or without the ID byte)
  and returns a `ControllerState` or a decode error; sequence gap counting; battery decode; a
  `Transport` enum carried in the state. Keep `InputReport` as the raw layer underneath.
- Accept when: every fixture file decodes with no errors; a test feeds a USB and a Bluetooth report
  of the same physical state and gets equal `ControllerState` values.

### M1-T5: Touch gesture engine

- Agent: coder
- Depends on: T4
- Owns: `Sources/DualSenseCore/Gestures/`, tests
- Do: `TouchGestureEngine` configured with a zone grid (1x1, 2x1, 1x2, 2x2, or custom rects in
  touchpad coordinates), `tapMaxDuration` (default 180 ms), `tapMaxMovement` (default 40 px),
  `holdMinDuration` (default 400 ms), `swipeMinDistance` (default 300 px), `swipeMaxDuration`
  (default 500 ms). Input: `update(touches: [TouchPoint], at: TimeInterval)` per report. Output:
  an array of `GestureEvent` values: `.tap(zone)`, `.twoFingerTap`, `.holdBegan(zone)`,
  `.holdEnded(zone)`, `.swipe(direction, zone)`, `.drag(dx, dy)`, `.touchpadClick(zone)` (from the
  button bit, passed in). Pure value semantics, no timers; time comes in with each update.
- Accept when: tests cover each gesture with synthetic sequences at 250 Hz, including: a slow move
  that must not be a swipe, a tap near a zone border, a swipe that starts in one zone and ends in
  another (reported by start zone), two fingers down within 50 ms as a two-finger tap, and a hold
  that ends with a swipe (hold ended, no swipe).
