## Questions for the architect

1. **Rumble (resolved by the owner, for the architect's information).** The spec described the driver as
   setting `valid_flag0 = 0x03` always and flag2 `0x04` on firmware >= `0x0224`. The kernel (L1332-1341,
   L1806) sets flag0 bit 1 always, then flag2 bit 2 on v2 firmware or flag0 bit 0 otherwise; the cutoff is
   `0x0215`. The owner chose kernel-faithful: `VibrationMode.v1` (flag0 `0x03`) and `.v2` (flag0 `0x02`,
   flag2 `0x04`), default v2; M2's DeviceManager reads feature `0x20` and chooses. Hardware confirmed both
   work on firmware `0x0633`. `M0-results.md`'s "flags match the Linux driver" was wrong. The spec's
   deliverable test (`valid_flag0 == 0x03`) now applies to v1 only.
2. Ordinals 101-103 (spec T6): Wine's `xinput1_3.spec` and `xinput1_4.spec` list nothing between 100 and
   108, and the ordinals doc says not to invent exports without a second source. T6 did not add them. If
   Fallout 4 turns out to need them, a second source is needed.

## Deviations from the spec

- Run as a local Mac session on branch `m1/core` (spec: cloud session, `claude/...` branch).
- Tests run with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test`. The Command Line
  Tools lack XCTest; Xcode.app is installed, so M0-mac Question 2 is answered: select Xcode for the command,
  no new install. `scripts/swift` picks the CLT toolchain and does not work for tests here.
- Subagent `git add`/`commit` is denied by the permission system, so the lead committed each task after
  running `swift build` and `swift test` itself, then dispatched the reviewer on the commit. The spec's
  "coder commits its own task" did not work.
- **T5 review failure was the lead's.** The lead briefed the first T5 coder from a stale copy of
  `specs/M1.md` (read on `m0/mac` before branching from `main`): the old version lacked the `padClicked` /
  `.padClick` names, the 65 Hz requirement and the fixture-test requirement. The coder followed the brief.
  This should not count against the Sonnet-lead experiment's review-failure signal; the T1 failure (cited
  facts, wrong numbers in a doc) is the genuine one. T1 was also briefed from the stale spec and extended
  by message.
- T5 ran before T4 (the engine needs only `TouchPoint`); T6 ran in parallel with T2.
- mingw-w64 was installed with `brew install mingw-w64` on the owner's yes. The Homebrew mingw has only a
  UCRT runtime, so the stub was rewritten CRT-free (`-nostdlib`, hand-written formatting) to import only
  KERNEL32. Both DLLs are untested in Wine or CrossOver.
- T6 pins the image base (`0x180000000`) and disables ASLR flags because the DLLs have no `.reloc`
  section. Reviewer flagged this as unverified; test it in the M2 Mac session.
- The two docs were written in the wrong order relative to code: `docs/protocol/xinput-ordinals.md` marks
  the `.def` `@N` ordinal syntax UNVERIFIED; T6 verified it with `objdump -p` (GetState 2, SetState 3,
  GetStateEx 100 in both DLLs).
- `TouchGestureConfigTests` (T5 scope) was committed under T4.
- Extra config field `twoFingerTapWindow` (default 50 ms) in `TouchGestureConfig`; implied by the spec.
